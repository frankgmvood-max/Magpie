# Инструменты для кодинга, анализа кода и реверс-инжиниринга

Дата проверки: **19 октября 2026 года**. Время метаданных и даты push в таблицах — UTC.

Проверено **44 GitHub-репозитория**: популярность, последнее время push, статус архивирования и определённая GitHub лицензия. Для основных кандидатов дополнительно изучены README, требования, лицензии и последние опубликованные релизы. В каталоге 43 проекта с более чем 5 000 звёзд и один более молодой официальный проект Hex-Rays, включённый из-за прямой рекомендации автора популярной альтернативы.

Это исследование первичных источников и состояния проектов, без установки программ и собственных сравнительных бенчмарков. Практические приоритеты и оценки избыточности — выводы автора обзора. Звёзды показывают популярность, а качество решения конкретной задачи требует проверки на своём проекте. Поле pushed_at показывает последний push в репозиторий, а не обязательно изменение продукта или выпуск версии. Число открытых issues в GitHub API может включать pull requests, поэтому оно не использовалось как рейтинг надёжности.

## Самые полезные выводы

- Для анализа нативных Windows EXE/DLL: **Ghidra + LaurieWired/GhidraMCP**; для наблюдения за исполнением — **x64dbg**.
- При наличии актуальной IDA: сначала рассмотреть **официальный HexRaysSA/ida-mcp**. Автор mrexodia/ida-pro-mcp прямо рекомендует перейти к нему.
- Для .NET-сборок: **dnSpyEx**, для Android DEX/APK: **JADX**, для структуры бинарных файлов: **ImHex**.
- Для работы агента с исходниками: **Serena + Context7**. Для переноса проекта в чат — **Repomix**; для графа архитектуры — **GitNexus** с учётом его лицензии.
- Для веб-разработки: **Playwright CLI** для браузерных действий, **Chrome DevTools MCP** для диагностики, обычный **Playwright** для повторяемых тестов.
- Среди кодинг-агентов разумно сравнивать OpenCode, Codex CLI, Claude Code, Gemini CLI и Cline на своей задаче. Установка всех сразу редко помогает выбрать рабочий процесс.
- Старые подборки могут вводить в заблуждение: **Roo Code закрыт**, **Continue сообщает о прекращении активного сопровождения**, а у Aider дата последнего push заметно старее, чем у основных активных конкурентов.

## Подтверждённые новости и изменения

**Официальный IDA MCP.** Hex-Rays представила собственный открытый сервер: взаимодействие через IDAPython, совместная работа с базами анализа и headless-режим. README требует IDA 9.4+, idalib и Python 3.11+. Публикация перечисляет IDA Pro, Home, Classroom и OEM; бесплатность MCP не означает бесплатность самой IDA. У страницы анонса в доступном представлении нет точной даты публикации, поэтому она не датирована предположительно. [Анонс](https://hex-rays.com/blog/hex-rays-ida-mcp-server), [репозиторий](https://github.com/HexRaysSA/ida-mcp), [рекомендация mrexodia](https://github.com/mrexodia/ida-pro-mcp).

Последний MIT-релиз приложения — 1.7.0; переход не ретроактивен. [Релиз](https://github.com/oraios/serena/releases/tag/v2.0.0), [лицензия](https://github.com/oraios/serena/blob/main/LICENSE).

**15 октября — Chrome DevTools MCP 1.11.0.** Добавлены средства анализа контекстов heap snapshot, улучшено сравнение снимков памяти, появилась запись экрана без ffmpeg; расширены настройки профилирования. Это полезно при диагностике памяти и воспроизведении проблем интерфейса. [Релиз](https://github.com/ChromeDevTools/chrome-devtools-mcp/releases/tag/chrome-devtools-mcp-v1.11.0).

MCP они сохраняют для сценариев с постоянным состоянием и подробным исследованием страницы. Это рекомендация разработчиков, а не собственный замер обзора. ## На что обратить внимание у главных кандидатов

**Ghidra и GhidraMCP.** Ghidra предоставляет анализ машинного кода; MCP открывает эти возможности ИИ-клиенту. Практический пример запроса: «Найди функции чтения конфигурации, покажи цепочку вызовов и пометь обоснованные выводы в комментариях». Имена из декомпиляции и объяснения модели могут быть гипотезами. Проверяйте их по вызовам, строкам, данным и наблюдаемому поведению. Восстановить таким способом оригинальные комментарии, полную структуру проекта и исходные имена после их удаления нельзя гарантировать.

**Две интеграции Ghidra — разные проекты.** LaurieWired/GhidraMCP — первый кандидат для знакомства. bethington/ghidra-mcp полезен, когда нужны пакетные правки, headless, управление типами и более широкий набор операций. Но у bethington текущий README dev-ветки говорит о 209 инструментах, а страница релиза 6.0.0 — о 272. Совместимость в релизе также указана для другой версии Ghidra. Это расхождение между источниками не позволяет выдавать одну цифру за универсальную; сравнивать следует конкретные закреплённые версии.

**Официальный IDA MCP.** Низкое относительно старого проекта число звёзд здесь объясняет, почему механическая сортировка недостаточна: источник — производитель IDA, и автор известного стороннего сервера сам направляет пользователей к нему. Это обоснованный приоритет при уже имеющейся подходящей IDA. Для полностью бесплатного старта практичнее Ghidra.

**x64dbg, Frida, ImHex.** Они отвечают на разные вопросы. x64dbg помогает остановить исполнение и проверить состояние процесса. Frida позволяет скриптами наблюдать и инструментировать функции во время работы. ImHex помогает понимать расположение полей в бинарных данных. Установка всех трёх имеет смысл, когда задача действительно охватывает эти уровни.

**Serena, GitNexus и Repomix.** Serena даёт агенту операции над символами и ссылками через языковой backend. GitNexus строит индекс и граф связей, полезный для исследования архитектуры и области влияния правки. Repomix собирает код в файл для передачи модели. Это взаимодополняющие способы получить контекст. Для малого проекта начинать сразу с полного набора может быть избыточно.

**Context7.** Полезен, когда агент использует библиотеку по устаревшей памяти. Лучше формулировать задачу с названием и версией зависимости, чтобы примеры соответствовали проекту. Наличие сервера не гарантирует полноту документации каждой библиотеки; условия доступа и лимиты сервиса нужно смотреть отдельно.

**Выбор кодинг-агента.** OpenCode интересен открытой реализацией и сочетанием терминала с desktop beta. Codex CLI и Gemini CLI — другие открытые варианты; Cline удобен для работы в редакторе. Claude Code — готовый продукт с публичным GitHub, но его LICENSE.md ссылается на Commercial Terms, поэтому называть всю эту подборку «полностью открытые и бесплатные агенты» неправильно. Стоимость интерфейса и стоимость работы модели — отдельные вопросы.

**Superpowers и Spec Kit.** Выбирать их стоит по характеру процесса. Уточнение требований и последовательная проверка полезны при сложной разработке; пользователь, которому нужны короткие прямые правки, может получить лишние вопросы и этапы. Их популярность не является независимым доказательством повышения качества именно вашего проекта.

**Проверка работы агента.** Playwright проверяет пользовательские сценарии, Chrome DevTools помогает исследовать сеть, консоль и производительность, Semgrep ищет классы проблем в исходниках, Ruff проверяет Python-стиль и часть ошибок. Каждый покрывает свой участок; зелёный результат одного инструмента не подтверждает всё поведение программы.

## Практический порядок знакомства

1. Выбрать один основной кодинг-агент: OpenCode, Codex CLI, Claude Code, Gemini CLI либо Cline — в зависимости от уже используемой модели и предпочтения терминала или редактора.
2. Для исходников сначала добавить Context7; Serena — когда появляется сложная навигация и рефакторинг.
3. Для реверса нативных программ начать с Detect It Easy, Ghidra и x64dbg. GhidraMCP добавляет ИИ к этому процессу. При актуальной IDA выбрать официальный IDA MCP.
4. Выбирать специализированный декомпилятор по формату: dnSpyEx для .NET, JADX для DEX/APK. Универсальная нативная декомпиляция не всегда будет самым удобным первым шагом.
5. Добавлять проверку под реальную задачу: Playwright для веб-сценариев, py-spy для Python-производительности, Semgrep для правил анализа исходников.
6. Beads, Vibe Kanban, Spec Kit и Superpowers рассматривать по мере роста задач и потребности в процессе.
