# Инструментарий для агента

Здесь хранится общий каталог инструментов для работы с исходниками, бинарными
файлами, браузером и производительностью. Корневой `AGENTS.md` направляет агента
сюда, когда задача выигрывает от специализированного инструмента.

- [Полное исследование 44 репозиториев](research-2026-10-19.md) — снимок на 19.10.2026.
- [catalog.json](catalog.json) — проекты, статусы, ссылки, доступные CLI и маршруты.
- [toolbox.py](toolbox.py) — локальный выбор маршрута и проверка команд.

Каталог не устанавливает программы и не создаёт MCP-подключения автоматически.
Агент проверяет текущее окружение и подключает нужный инструмент в рамках задачи.
Сам скрипт работает на Python 3.9+ без сторонних зависимостей, не обращается к сети,
не запускает найденные программы и не меняет настройки компьютера.

## Быстрый запуск

Из корня репозитория:

```bash
python tools/agent-toolbox/toolbox.py list
python tools/agent-toolbox/toolbox.py plan native-static
python tools/agent-toolbox/toolbox.py doctor --task native-static
python tools/agent-toolbox/toolbox.py doctor --task source-navigation --json
```

На Windows можно использовать `py -3`, на Linux/macOS — `python3`, если команда
`python` недоступна. Проверка команды в PATH означает только наличие файла, а не
полноту установки, работоспособность лицензии или активное MCP-соединение.
Параметр `--strict` у `doctor` возвращает код 1, если не все инструменты маршрута
обнаружены; обычная проверка носит информационный характер и возвращает 0.

## Выбор по задаче

| TASK | Когда использовать | Инструменты |
|---|---|---|
| `native-static` | Анализ нативных EXE/DLL без выполнения | Detect It Easy, Ghidra, GhidraMCP |
| `native-debug` | Проверить выполнение Windows-программы | x64dbg, Frida |
| `ida-analysis` | Анализ при наличии подходящей IDA | Официальный Hex-Rays IDA MCP |
| `dotnet` | Управляемые .NET EXE/DLL | dnSpyEx |
| `android` | Код DEX/APK | JADX, Frida |
| `binary-format` | Структура бинарных файлов | ImHex, LIEF |
| `source-navigation` | Символы, ссылки и документация библиотек | Serena, Context7 |
| `source-rewrite` | Повторяющиеся структурные изменения | ast-grep |
| `repo-handoff` | Подготовить код проекта для передачи модели | Repomix |
| `web-debug` | Консоль, запросы и производительность Chrome | Chrome DevTools MCP |
| `web-test` | Браузерный сценарий и регрессионные проверки | Playwright CLI, Playwright |
| `source-check` | Проверка классов ошибок в исходниках | Semgrep |
| `python` | Python-окружение, стиль и профилирование | uv, Ruff, py-spy |
| `native-profile` | Измерение производительности своего проекта | Tracy |
| `http-analysis` | Исследование HTTP/HTTPS-обмена | mitmproxy |
| `git-review` | Просмотр изменений и Git-операции | lazygit |
| `long-tasks` | Зависимости и память длительной разработки | Beads |

Маршрут — перечень кандидатов. Можно использовать только нужную часть, подходящую
для платформы. Например, x64dbg рассчитан на Windows, а LIEF — библиотека, а не
самостоятельный универсальный декомпилятор. Собственный MCP-клиент тоже нужен:
наличие GhidraMCP в каталоге не открывает локальную Ghidra облачному чату.

## Как применять агенту

1. Определить вопрос, на который должен ответить инструмент: найти символ,
   восстановить цепочку вызовов, воспроизвести сбой, измерить узкое место.
2. Проверить уже предоставленные клиентом возможности. Не менять основной
   кодинг-агент только из-за наличия альтернативы в каталоге.
3. Запустить `plan` и `doctor` для подходящего TASK. Если команды нет в PATH,
   проверить также конфигурацию MCP-клиента: сервер мог быть задан через `uvx`,
   `npx`, абсолютный путь или другой хост.
4. Перейти по `setup_docs` выбранного инструмента. Сверить поддержку платформы,
   актуальный выпуск, условия лицензии и зависимости. В рамках разрешённой задачи
   установить только нужные компоненты в отдельное окружение или каталог кеша.
5. Зафиксировать использованную версию и точную команду/клиент. Для MCP проверить
   подключение и получить реальные результаты инструмента.
6. Подтвердить вывод исходниками, ссылками на адреса/функции, воспроизводимым
   сценарием либо измерением. Если окружение не позволяет применить инструмент,
   явно указать ограничение и продолжить доступным способом.

Не требуется устанавливать все 44 проекта. В каталог входят и альтернативные
агенты, и библиотеки, и исследовательские проекты с разными требованиями.

## Использование в другой ветке или проекте

Инструкции автоматически доступны агенту в checkout, где присутствует `AGENTS.md`.
Для старых веток можно перенести этот набор файлов отдельным коммитом, не смешивая
изменения исходников. Для другого проекта достаточно добавить ссылку на этот
каталог в его собственные инструкции и при необходимости скопировать скрипт с JSON.
Хранение на GitHub само по себе не меняет глобальные настройки будущих чатов.
