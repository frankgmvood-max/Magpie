Magpie 0.6.9-vrr2 — VRR/G-SYNC, шкала Optical Flow и исправление запуска Reflex

Эта сборка основана на Magpie Experimental 0.6.9 (код 2fceab5e). Сохранены DLSS SR/FG/NR, AMD FSR/Optical Flow, XeSS и RTX Video/HDR. Физическое изменение частоты монитора на RTX 3080 ещё не подтверждено: тесты Windows/WARP проверяют код и API, но не NVIDIA scanout.

Полный пакет

Magpie-0.6.9-VRR2-full-x64.zip можно распаковать в отдельную новую папку и запустить находящийся внутри Magpie.exe. Затем перенеси из своей рабочей папки только свой совместимый FG runtime для RTX 3080 и его необходимые DLL/настройки. В полном пакете исходные NVIDIA runtime из релиза 0.6.9; они не содержат твой мод совместимости RTX 3080. Все прочие компоненты исходного полного релиза сохранены.

Установка обновления

1. Полностью закрой Magpie, включая значок в трее.
2. Скопируй свою рабочую папку Magpie 0.6.9 в отдельную папку. Для другой версии сначала распакуй официальный полный пакет 0.6.9.
3. Содержимое Magpie-0.6.9-VRR2-update-x64.zip скопируй прямо в эту папку, рядом с Magpie.exe, с заменой файлов. Оно подходит и для уже установленной полной VRR1-сборки.
4. Обновление содержит приложение, ресурсы интерфейса и эффекты. Оно не заменяет nvngx_dlssg.dll, DLL мода для RTX 3080 и прочие NVIDIA runtime. Сохрани именно свои файлы, с которыми FG уже работает. Официальный DLSS FG на RTX 3080 сам по себе не запускается.
5. Запусти новый Magpie.exe. Новые файлы не надо переносить в LS или в его addon manager.

Начальные настройки для Xiaomi Mi 34, 3440×1440, 144 Гц, RTX 3080

- В панели NVIDIA включи G-SYNC для оконного и полноэкранного режима, а также для выбранного монитора. Видеорежим Windows — 144 Гц. Не запускай старые Activate/Deactivate BAT-профили вслепую: эта сборка не требует новых глобальных изменений драйвера.
- На главной странице Magpie открой «VRR / G-SYNC». Включи переключатель, поставь конечный лимит 136 FPS, вывод «Composition flip». Значение 0 выбирает автоматический запас 5%: при 144 Гц получится 136 FPS.
- Выбери полноэкранное масштабирование оконной игры. При обычном маленьком окне Windows может оставить композицию DWM; наличие ALLOW_TEARING не гарантирует Independent Flip.
- В эффекте DLSS FG начни с множителя x2. Для конечных 136 FPS нужны устойчивые 68 исходных FPS и запас GPU на захват, эффекты и генерацию. Ограничь FPS самой игры до 68: конечный лимит Magpie не меняет внутренний FPS игры. Сам лимит не создаёт недостающие исходные кадры. При x3 нужно около 45.33, при x4 — 34 исходных FPS; поддержка множителя зависит от твоего FG runtime.
- При фиксированной синхронизации кадров в Magpie выставь исходный целевой FPS 68 для x2, либо выбери Auto. Общий VRR-лимит применяется после умножения и учитывает обновления курсора. Если оставить исходную цель 60, x2 даст максимум 120, а не 136.
- Reflex включается только при включённой синхронизации кадров с явно выбранным режимом Reflex. DLSS FG больше не запускает его автоматически. При выключенной синхронизации или выборе FrontEdge/Async генерация и отдельный VRR-лимит продолжают работать без NVAPI Reflex. Для первого запуска на RTX 3080 оставь Reflex выключенным.
- Выбор видеокарты «Автоматически» при VRR ищет RTX, к которой подключён монитор; это важно при двух RTX 3080. Явный выбор другой карты сохраняется, но может требовать межадаптерного копирования.
- Optical Flow: метод NVIDIA, качество Balanced, «Разрешение Optical Flow (%)» сначала 50. Шкала допускает 25–100%. Меньший процент уменьшает площадь анализа, но может ухудшить мелкие движения и окклюзии; 50% — примерно четверть пикселей анализа, а не гарантия четырёхкратного ускорения всей FG. При нескольких потребителях OF используется общий наиболее высокий запрошенный процент. На GPU без сетки 2×2 верхние профили используют 4×4 при том же уровне вычисления, с сообщением в логе.
- Настройки VRR/режима вывода и OF применяются при новом запуске масштабирования.

Что изменено

В VRR1 DLSS FG автоматически запускал Reflex даже при выключенной синхронизации. В двух присланных попытках последний записанный вызов — отказ D3D12 async generation marker при actualOn=false; обработчик затем повторно обращался к драйверу для отключения Reflex. VRR2 убирает автоматический запуск. При actualOn=false необязательные async-маркеры не вызываются. Отказ любого async-маркера отключает этот канал до конца сеанса, не вызывая SetSleepMode посреди генерации и сохраняя обычный pacing. Отсутствие необязательных API тоже не мешает обычному Reflex.

Нативные вызовы Reflex защищены от Windows SEH на вызывающем потоке: код, адрес и поток исключения записываются в лог, дальнейшие входы в этот экземпляр NVAPI блокируются. Если после исключения нельзя подтвердить снятие ранее заданного драйверного лимита, сеанс останавливается вместо небезопасного продолжения. Защита не ловит ошибки чужого фонового потока и не доказывает, что найден единственный источник падения. Исправление проверено тестами, подтверждение на твоём RTX 3080 требует запуска новой сборки.

DXGI composition flip-chain прикреплена к DirectComposition visual. Это настоящая обменная цепочка с Present, а не прежняя виртуальная поверхность DComp. Используются Present(0), ALLOW_TEARING при поддержке, три буфера и MaximumFrameLatency=1; флаги сохраняются при ResizeBuffers. Если Windows не создаёт composition-chain, предусмотрен переход на HWND flip; его также можно выбрать в меню.

Фронтенд готовит кадр до срока вывода, затем использует общий фазовый таймер. Время блокировки Present и ожидания очереди не становится новым периодом. После долгой паузы старый график сбрасывается без залпа кадров. Курсор рисуется в текущем выводимом кадре; повторы старого изображения не вставляются в работающую последовательность FG без явного действия интерфейса.

Для OF используется линейное уменьшение в поддерживаемую BGRA render target, затем векторы пересчитываются в пиксели исходного кадра. Сброс истории сохраняется до первого фактического запуска NVOF. После отключения FG пересчитывается исходный лимит. Потеря устройства/фатальная ошибка Present останавливает сеанс; ожидание публикационного GPU fence ограничено двумя секундами.

После прогрева делается однократное чтение состояния G-SYNC/NVIDIA VRR. В логе «GSyncActive» и «displayInVrrMode» — сведения драйвера, а не измеренная частота развёртки. Окончательный результат проверяется по движению, OSD монитора и интервалам реально показанных кадров. Фиксированные 144 Гц при активном индикаторе NVIDIA всё ещё требуют проверки: индикатор сам по себе не доказывает переменную развёртку.

Проверки сборки

Автоматические тесты выполняются на Windows с программным Direct3D WARP. Они проверяют реальные HLSL преобразования и масштаб движения, confidence, нечётные размеры, HDR/SDR, создание composition flip-chain, Present/ResizeBuffers, native mouse transparency и отсутствие смены фокуса. Отдельные тесты проверяют миллион шагов фазового таймера, конечные лимиты x1–x4, паузы, timestamps захвата и сбросы OF. Исходники и результаты Windows CI доступны в ветке magpie-vrr-0.6.9 репозитория frankgmvood-max/Magpie.

Для VRR2 добавлены 192 варианта фактического Renderer startup, отсутствие NVAPI-вызовов при выключенном Reflex, семь точек отказа основного Reflex и девять точек отказа необязательных async-маркеров, сохранение принятого лимита, отсутствие повторных попыток после ошибки и восстановление после сворачивания. Отдельный Windows-тест вызывает настоящее SEH-исключение и проверяет его перехват, блокировку повторного входа, безопасность очистки лимита и отсутствие блокировки Present спящим потоком.
