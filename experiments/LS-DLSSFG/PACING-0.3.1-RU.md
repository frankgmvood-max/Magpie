# LS DLSS FG 0.3.1: pacing и один сравнительный замер

Это исправление CPU-подачи кадров поверх существующего LS DLSS FG для RTX 3080.
Ваш рабочий runtime/mod не меняется. Гарантии физического VRR и ровных 136 FPS
пока нет: для этого нужен замер на ваших двух RTX 3080 и подключённом мониторе.

## Установка обновления

1. Полностью закройте LS, включая значок в трее.
2. Из архива скопируйте LS_OutputBridge.dll в папку LosslessScaling.exe,
   а папку addons — в её addons, согласившись на замену файлов.
3. Запустите LS. Версия DLSS аддона должна быть 0.3.1.
   Существующий LS_DLSSFG.ini, папка runtime, настройки/профили и другие аддоны
   не входят в заменяемые файлы обновления.

Target output FPS задаётся именно в Settings DLSS аддона. Поле target в LS
является отдельным параметром, и при выключенном native FG не подтверждает
значение cap нашего аддона. Для x2 / 136: игра 68 FPS, аддон 136, очередь 1,
Request VRR включён, Present API Follow LS. Сохраните текущий OF для первого
сравнения. Continuously query driver G-SYNC оставьте выключенным.
Состояние G-SYNC в аддоне кэшируется; кнопка Refresh обновляет его вручную.

## Два замера по минуте

Первый контроль сделайте на 120 FPS, чтобы отделить выход у верхней границы
144 Гц от самого пути вывода. Одна и та же игра, сцена, захват LS и ограничение
игры 60 FPS; монитор остаётся в режиме 144 Гц. Не меняйте OF между запусками
DLSS, не включайте два генератора одновременно. SM и HDR выключены для сравнения.

1. Включите native LSFG x2 / 120, DLSS аддон выключите.
   Запустите scaling и `Capture-Native-LSFG.cmd` из папки `addons/LS_DLSSFG`.
2. Полностью перезапустите LS. Native LSFG выключите, DLSS FG включите:
   x2 / Target output FPS 120, Maximum Frame Latency 1, тот же OF.
   Запустите scaling и `Capture-DLSSFG.cmd`.

Windows попросит права администратора для ETW. После начала вернитесь в игру:
задержка перед записью 5 секунд, длительность 60 секунд. Окно менеджера,
FPS/DRR Tool и внешние оверлеи держите закрытыми во время замера. При наличии
нескольких мониторов сравнивайте один и тот же экран, а его OSD наблюдайте
отдельно. Сборщик не меняет настройки LS/драйвера и не отправляет файлы.
Режим в capture.json является вашей меткой, а не автоматически проверенным
состоянием штатного FG.

На рабочем столе появятся два `LS-Pacing-*.zip`. Внутри — PresentMon CSV,
текущий лог менеджера, INI/версия DLSS аддона, сведения о драйвере/двух GPU.
Для включённого DLSS 0.3.1 добавится собственная CPU-трасса генератора;
она стартует автоматически по запросу сборщика и завершается за 60 секунд.
Если она отсутствует/неполна, приложите сохранившийся архив: это сообщается
в collection/capture warnings. Копия логов может содержать предыдущие запуски;
PID и время замера указаны в capture.json.

Используется официальный portable PresentMon 2.6.0 с проверкой SHA256:
`b2a706bc6ad475749e3b7e3409263aa1e6906d45bdcf993f6dbc0f660188f1af`.
Первый запуск скачает EXE из GameTechDev/PresentMon на GitHub в LOCALAPPDATA.
MSI/служба/оверлей не устанавливаются. Сессия ETW имеет уникальное имя;
чужие сессии не останавливаются. Клавиатура/мышь не записываются.

## Что именно проверяется

CPU-трасса содержит тип кадра, начало/конец реального DXGI вызова, QPC,
его частоту, дедлайн, время обработки и ожидания очереди. Это позволяет найти
неравномерность подачи и блокирующий Present. Все записи уходят на диск из
фонового потока; количество потерянных строк указано в конце CSV.

PresentMon показывает режим/времена вывода и пропуски по событиям Windows.
Он не гарантирует доступность всех метрик на любом драйвере и не измеряет
физическую электронику панели. FrameType не считается доказательством FG:
автоматическая классификация требует инструментирования драйвера/приложения.
В нашем CSV `kind=0` — реальный, `1` — сгенерированный, `2` — дубликат,
`3` — кадр истории/выход, на котором runtime не дал интерполяцию.

Лог FPS Monitor не содержит точных времен каждого кадра. Его название/формат
похожи на Microsoft DRR Tool. В исходном инструменте считается compositor
clock и используются широкие категории частоты; порог именно вашей версии
с добавленным 144 Гц не проверен. Поэтому 96% отсчётов в категории 144 не является
доказательством фиксированных 144 Гц панели. Для Independent Flip Microsoft
прямо предупреждает о неполных compositor statistics.

После этих двух записей можно различить: нестабильную CPU-подачу, задержки
очереди/вывода Windows, неверный измеряемый монитор и проблему, общую для native
LSFG и DLSS. Только затем имеет смысл выбирать исправление владения выводом
или отдельный presenter. Одновременный Present на swapchain LS из другого
потока пока не добавляется: LS может перезаписать/пересоздать буферы.

Источники и границы проверки — в RESEARCH.md. CI проверяет код на Windows/WARP,
а не реальный RTX DLSS runtime или ваш монитор.
