# DLSS FG для Lossless Scaling — эксперимент 0.3.0

Аддон для Echo-Storm/ls-addon-manager 0.9.38, API 1.1+. DLSS FG x2–x4,
аппаратная оценка движения NVIDIA Optical Flow и фильтрация повторных кадров.
Обработка выполняется на GPU вывода LS; дополнительное устройство D3D11
использует тот же адаптер и не изменяет состояние рендера LS.

## Обновление с 0.1.3 / 0.2.0

Полностью закрой LS. Распакуй **update.zip** поверх папки установленного LS:
внутри архива находится только `addons/LS_DLSSFG`. Этот архив не заменяет
твой `LS_DLSSFG.ini`, runtime, рабочий мод SM86, профили и файлы менеджера.
Включи аддон. Новые настройки находятся на странице аддона в менеджере.
При отсутствии новых ключей используются x2, NVOF Balanced, масштаб анализа
OF 50%, точная фильтрация повторов. Старые PreferVRR, TargetFPS, MaximumFrameLatency и подтверждение
выключенного LSFG сохраняются. Нажми Save and apply после изменения настроек.

## Первая установка

1. Установи менеджер LS. Полностью закрой LS и распакуй `x64.zip` в папку LS.
2. В `addons/LS_DLSSFG/runtime` оставь свой **рабочий совместимый**
   `nvngx_dlssg.dll` и необходимые ему DLL. На RTX 3080 требуется совместимый
   мод. NVIDIA runtime/мод не входят в архив. Не подменяй Lossless.dll менеджера
   процессным прокси SM86 и не клади proxy loaders в папку runtime.
3. Выключи штатный LSFG в профиле LS. Включи аддон и на его странице отметь
   `I have disabled native LS frame generation`, затем Save and apply.
4. Сохрани проверенные настройки масштабирования, захвата и курсора LS.
   Для начала на RTX 3080: x2, NVOF Performance, OF Analysis Resolution 50%,
   Duplicate Frame Filtering включён,
   Target output FPS 136, очередь 1, Present API Follow LS.
5. Для x2/136 ограничь игру до 68 исходных FPS. При нехватке стабильного входа
   используй Adaptive output pacing. x3/136 требует примерно 45.33 исходных
   FPS; x4/136 — 34. Высокий множитель не улучшает отклик до выходного FPS.

NativeLSFGDisabled — подтверждение пользователя; SDK менеджера не предоставляет
состояние штатного LSFG. Одновременная работа двух генераторов не поддерживается.
Штатный масштабатор/захват/окно/курсор LS сохраняются. GPU-аддоны, перечисленные
в conflicts манифеста, одновременно не включаются.

## Optical Flow

В 0.3.0 добавлен **OF Analysis Resolution: 25% / 50% / 75% / 100%**.
По умолчанию — 50%. Для 3440×1440 анализ выполняется на 1720×720,
то есть на четверти исходного количества пикселей. Это не обещание ускорения
в четыре раза: плотная карта движения и DLSSG остаются в исходном разрешении.
Векторы отдельно масштабируются по X/Y в пиксели полного изображения;
минимальные размеры анализа проверяются у драйвера. Меньший масштаб может
ухудшить точность мелких движений. Начни с 50% + Performance; если результат
хуже варианта без OF, можно выбрать None. Повышать профиль OF при рывках
не следует: высокая детализация добавляет работу.

* None: нулевые векторы движения, прежний режим аддона.
* NVIDIA NVOF: движение текущего изображения к предыдущему, в пикселях;
  значения S10.5 аппаратного OF преобразуются в плотную R16G16_FLOAT карту.
* Пять профилей: Performance 4x4/Fast, Balanced 4x4/Medium, Quality 4x4/Slow,
  High Quality 2x2/Medium, Highest Quality 2x2/Slow. Доступность сетки проверяется
  у драйвера. Неподдерживаемый 2x2 заменяется соответствующим 4x4 и сообщается
  в логе/меню; отказ NVOF переводит FG на None со сбросом истории.
* Драйверный nvofapi64.dll загружается только из System32. Дополнительные
  OF/CUDA DLL от пользователя не нужны. Первый кадр/пауза/смена настроек
  обнуляют историю, а первая следующая пара отключает старые temporal hints
  драйвера. Нулевое движение неподвижного пикселя считается допустимым вектором.
  scRGB преобразуется в SDR **только для анализа движения**;
  исходные цвета LS и изображение DLSSG не преобразуются.

Оценка по снимкам не заменяет motion/depth от движка. Глубина нулевая, HUD и
захваченный курсор остаются частью изображения. Более высокое качество OF
имеет стоимость и не гарантирует меньше артефактов в каждой игре.
AMDOF в этой сборке не реализован; выбирать его в меню нельзя.

## Frame Multiplier

x2/x3/x4 — запрос к runtime. Реальный максимум читается при запуске,
неподдерживаемый запрос снижается до доступного, отсутствие capability означает
x2. Интерфейс показывает эффективный множитель. При сбросе истории NGX получает
1/1, в обычной группе — 1..M-1 с единым BackbufferFrameID. Каждый промежуточный
кадр имеет отдельную текстуру; оригинальный кадр LS восстанавливается после
последнего flip. Запрос более высокого множителя не включает поддержку RTX 3080
в штатной DLL NVIDIA.

## Duplicate Frame Filtering

Корректное название — **фильтрация повторных кадров**, Duplicate Frame Filtering.
Принцип из Magpie 0.6.9: точное сравнение всех RGB-пикселей с предыдущим принятым
кадром. Альфа не сравнивается. В аддоне проверяется **выход LS перед нашим FG**,
поскольку менеджер не предоставляет исходный capture callback. Поэтому анимация
оверлея/встроенного курсора может сделать одинаковые кадры игры различными.

Повтор пропускает NVOF и DLSSG, не обновляет временную историю и не влияет на
исходный Present LS. Отменять Present LS небезопасно для его окна/курсора.
Данные сравниваются на GPU, читается один uint, максимум ожидания 500 мс;
проверка имеет стоимость. Фильтр отключается при ошибке чтения с записью в лог.
Неполученные кадры игры фильтр не восстанавливает и гладкий график не обещает.

## VRR и настройки вывода

* Request windowed VRR-compatible Present: sync=0/ALLOW_TEARING для законно
  созданной оконной flip swapchain; исходный Present тоже получает политику.
  Если условия не выполнены, настройки LS сохраняются. Флаг не включает G-SYNC
  принудительно и не превращает composition в Independent Flip.
* Maximum Frame Latency: 0 сохраняет очередь LS; 1/2/3 задают ограничение.
  Выбирается правильный API устройства/swapchain. Значение возвращается при
  остановке, сбросе и ошибке; более новое изменение LS не перезаписывается.
* Generated frame Present API: Follow LS / Present / Present1. Follow LS —
  рекомендуемый. Альтернативы меняют только полные промежуточные кадры.
  Исходный API LS, dirty/scroll/TEST/nonblocking-семантика сохраняются.
* Если у цепочки уже есть waitable queue handle, он используется; новые флаги
  создания/собственная swapchain/окно и принудительный fullscreen не добавляются.
* Adaptive рассчитывает шаг по уникальным входам и эффективному множителю;
  Target FPS задаёт шаг явно. Опоздавшие кадры не отправляются пачкой для
  «догоняния» расписания. Генерация и ожидания пока находятся в потоке вывода LS.

В 0.3.0 опрос G-SYNC, Media Statistics и публикация метрик выполняются
**после исходного Present LS**, а не между промежуточным и настоящим кадрами.
Начальный запрос до первого Present удалён: NVIDIA не гарантирует его
достоверность, а сам вызов может занимать заметное время.

Меню показывает результат запроса драйверу G-SYNC: active/inactive/unknown,
эффективное OF quality, время обработки, интервал уникальных входов и счётчики.
Unknown — запрос недоступен/неуспешен, не доказательство выключенного VRR.
Active означает ответ драйвера для устройства/поверхности, а не измеренную
частоту развёртки монитора. Если OSD монитора по-прежнему показывает фиксированную
частоту и изображение рвётся, VRR нельзя считать исправленным по одной этой строке.
Значение Media Statistics composition=1 означает Overlay; оно само по себе
не доказывает работу VRR. В статусе сообщается, когда время обработки превышает
бюджет выходного шага: Target FPS тогда не обеспечивает нужную производительность.

Лог менеджера: `logs/LSAddonManager.log`; начальные ошибки —
`%LOCALAPPDATA%/LS-DLSSFG/startup.log`. Строка FG output содержит flowScale,
queryAfterRealPresent=1 и monitorHz=unmeasured. Счётчик submitted
означает успешные Present, а не доказанное число кадров на мониторе.

На проверке VRR убери окно менеджера с игрового изображения. Реальное включение
G-SYNC на RTX 3080 и твоём мониторе не подтверждается автоматическими тестами.
В RESEARCH.md перечислены проверенные условия и архитектурные ограничения.

## Проверка и сборка

C++17, Windows x64 MSVC /MT. EAM SDK, NGX и ImGui закреплены по commit SHA.
NVOF declarations и их лицензии находятся в third_party/nvof.
NVAPI headers получает scripts/Fetch-NvapiHeaders.ps1 с проверкой SHA-256.

CTest проверяет настройки/MFG reset/pacing, ABI/lifecycle и отрисовку меню,
Present/Present1, восстановление очереди, точный GPU duplicate filter на WARP
(RGBA8/BGRA8/scRGB), OF conversion/densify/reset/failure на настоящих WARP-шейдерах
с **имитированным** драйвером NVOF. Это проверка контракта/кода, не тест реального
аппаратного OF, DLSSG или VRR. Исходники и лицензии включены в пакет.
Отдельная проверка на WARP выполняет реальную цепочку D3D11 LS → приватный
D3D11 → D3D12 → D3D11 LS, проверяет shared textures/fences и сохранение
состояния шейдера LS. Она также не заменяет испытание драйвера NVIDIA.
Проверки 0.3.0 дополнительно охватывают все масштабы OF, минимальные размеры
драйвера, нечётные размеры, пространственный градиент, пересчёт ненулевых
векторов, порядок статистики после настоящего кадра и защиту от рекурсии.
