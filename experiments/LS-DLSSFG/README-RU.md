# DLSS FG для Lossless Scaling — эксперимент 0.1.1

Отдельный аддон для Echo-Storm/ls-addon-manager, API 1.1+. Генерирует один
промежуточный кадр между двумя кадрами LS и показывает его через swap chain LS.
Использует D3D11 → D3D12 → NGX DLSSG → D3D11 на **GPU вывода LS**. Вторую GPU
для DLSSG аддон не выбирает: обмен между адаптерами пока не реализован.

## Установка

1. Закрой LS. Скопируй из архива папку `addons/LS_DLSSFG` в папку
   `addons` установленного менеджера. Другие файлы LS заменять не нужно.
2. В `addons/LS_DLSSFG/runtime` положи совместимый `nvngx_dlssg.dll` и
   необходимые DLL его окружения. На RTX 3080 нужен тот совместимый комплект,
   который уже работает у тебя с FG; обычная DLL NVIDIA этого не обеспечивает.
   Если мод использует процессный загрузчик `version.dll`/`dxgi.dll`, его
   совместимость с менеджером нужно решить отдельно. Аддон не загружает такой
   прокси из runtime и не заменяет прокси менеджера.
3. **Выключи встроенную генерацию LSFG в LS.** Для первого запуска оставь
   остальные проверенные настройки LS и курсора. Запусти
   `Activate-136FPS.cmd` в папке аддона, включи аддон в менеджере и перезапусти LS.
   Для профиля 136 ограничь реальные кадры игры до 68 FPS. Если входной поток
   не выдерживает 68, используй `Activate-Adaptive.cmd`.

`NativeLSFGDisabled=1` — подтверждение настройки со стороны пользователя,
а не автоматическое определение LSFG. Не включай оба генератора одновременно.

## Что уже реализовано

- Выбор вывода по backbuffer, записанному compute-проходом LS. Окно менеджера
  исключается без определения по названию/размеру окна.
- Общие текстуры D3D11/D3D12, две GPU-fence для передачи входа и результата,
  проверка флага NGX `OutputDisableInterpolation` после завершения GPU.
- Сброс истории после паузы, изменения размеров, устройства или настроек.
- Возврат настоящего кадра **в следующий буфер** после flip.
- Сохранение sync interval/flags LS. Для sync=0 — разнесение кадров пары,
  высокоточный таймер и ограниченное ожидание без повышения приоритета.
  Для sync=1 дополнительное ожидание не добавляется; частоту задаёт vsync LS.
- Отказ от TEST/DO_NOT_WAIT, необычных present flags и частичных Present1.
- Если NGX недоступен или вернул ошибку — пропуск обычных кадров LS,
  статус причины и метрики в менеджере. Повтор после отказа требует рестарта.
- Окно, фокус, захват мыши и отрисовка курсора остаются под управлением LS.

## Границы результата

Это **скомпилированный прототип**, не подтверждённая работа на твоём ПК.
Целевой интервал 136 FPS не создаёт недостающие исходные кадры. FG и Present
выполняются на потоке вывода LS, поэтому возможен обратный эффект на его темп
захвата. Ровную линию и сохранение эффективности синхронизации LS надо измерить
на реальном запуске. Зелёный статус означает успешные вызовы/Present, а не
подтверждение реального показа монитором или G-SYNC Active.

У LS нет глубины сцены, игровых motion vectors и данных камеры. Сейчас
передаются виртуальные нулевые depth/motion и изображение с HUD/курсором.
NGX использует доступную ему обработку изображения; качество при движении,
HUD и курсоре не равно интеграции DLSS FG в движок. HDR10 не поддержан;
принимаются RGBA8/BGRA8 SDR и scRGB. Поддержка runtime не гарантирована даже
для принимаемого формата.

## Исправление запуска в 0.1.1

При инициализации и DEVICE_READY аддон больше не обращается к последнему
borrowed-устройству из менеджера. Present-hook устанавливается только внутри
живого compute-прохода, который действительно записал выходной backbuffer.
Регистрация и удаление callback выполняются вне mutex аддона: это устраняет
обратный порядок блокировок с потоком Dispatch менеджера.

Запуск пишет этапы и код/адрес исключения в
`%LOCALAPPDATA%\LS-DLSSFG\startup.log`. При исключении сохраняется индикация
Faulted менеджера; ошибка не маскируется успешным статусом. Регрессионная
проверка использует намеренно недействительный указатель старого устройства.

Для обновления полностью закрой LS и замени **LS_DLSSFG.dll и addon.json**.
Твои LS_DLSSFG.ini и runtime оставь на месте. Версия карточки должна стать 0.1.1.

## Возврат к обычному LS

Запусти `Deactivate.cmd`, выключи аддон в менеджере и перезапусти LS.
После этого можно снова включить LSFG. Удаляется только папка этого аддона.

## Сборка

Точные версии: менеджер `fbcc3c179e4052785c032d157d8eb785608eb28e`, NVIDIA SDK
`374959484e79a640feaba44c93ac8cfb0a03f5b5`.

```powershell
cmake -S experiments/LS-DLSSFG -B out/ls-fg -A x64 -DEAM_ROOT=<manager> -DNGX_ROOT=<NVIDIA-DLSS>
cmake --build out/ls-fg --config Release
ctest --test-dir out/ls-fg -C Release --output-on-failure
cmake --install out/ls-fg --config Release --prefix out/package
```

Проверки без NVIDIA GPU проверяют SDK exports, запуск/остановку, события
замены устройства, расчёт интервалов, выбор compute-вывода и сохранение
Present при отказе FG на программном WARP-адаптере. Они не проверяют inference, VRR,
цвета, курсор или совместимость модифицированного runtime.
