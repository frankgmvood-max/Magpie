# Smooth Motion для LS 0.1.0 — эксперимент

Это отдельный NVIDIA NvPresent backend на основе MIT-кода ItsAdeline/NVSmooth30,
commit 21fa43521c2753ffd5c8e9d2092cfc79f9c6c456. Не требуется proxy version.dll/dxgi.dll; менеджер не заменяется.
Отключите штатный LSFG и аддон DLSS FG. В меню Smooth Motion включите функцию, подтвердите отключение LSFG и сохраните.
Множитель драйвера x2. Для 144 Гц профиль 136 FPS ограничивает подачу до 68 базовых FPS; игра должна стабильно отдавать базовые кадры.

NvPresent64.dll выбирается из уже загруженного активного пакета драйвера. Старые каталоги DriverStore не перебираются по дате.
NVIDIA/мод-бинарники не включены. В текущей версии разрешён один опубликованный анализируемый профиль:
SHA256 cd395d58f41c6e393c31a9898f2be3da83f7bc109a2228935c23e8c89b944c15.
Это ограничение версии NvPresent, не обещание поддержки всех драйверов RTX 3080. Для неизвестной версии патчи не применяются.
Мод nvngx_dlssg.dll относится к другому генератору и здесь не нужен.

D3D12 имеет тот же LUID, что GPU вывода LS. Default-путь проверяется заранее и после создания устройства.
Каждый HWND получает один swapchain. Вывод находится в отключённом дочернем окне LS, без переключения фокуса.
Пока модель прогревается, отображается базовый кадр. Статус генерации требует wrapper и успешного CUDA graph launch.
Tearing применяется только к созданной с ним цепочке и sync=0. При отсутствии инференса VRR-цепочка один раз заменяется reference plain descriptor.
После двух неудачных прогревов вывод LS сохраняется, backend останавливается. После остановки или смены драйвера перезапустите LS.
Аппаратная работа генерации и VRR на двух RTX 3080 не подтверждена тестами WARP.

В меню: целевой FPS, режим синхронизации, VRR-запрос, фильтр повторов, восстановление, путь создания устройства,
сохранение исходного LS Present, diagnostics и необязательный путь NvPresent. Путь должен соответствовать вашему пакету NVIDIA.
RTX HDR этого комплекта может передать FP16 scRGB без второго преобразования.
