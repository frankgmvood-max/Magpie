# Native DLSS для Lossless Scaling 0.1.0 — экспериментальная сборка

Это самостоятельный `Lossless.dll`. Менеджер аддонов для работы не нужен.
LS сохраняет захват, масштабирование, курсор, окно, очередь и собственные Present.
Новый backend берёт два исходных изображения LS и условно заменяет его
промежуточный кадр на результат NVIDIA. Собственного вывода кадров здесь нет.

**Поддерживается оригинальная DLL из твоего архива LS 3.2.2, LSFG3 Fixed ×2,
SDR, один midpoint. Поддержка проверяется по SHA256 DLL и двух проходов.**
Adaptive, другие множители, HDR, несовпавшие пары и другие версии остаются
на штатном LS. Установщик откажется заменять файлы другой версии.

## Установка

1. Полностью закрой LS, включая трей.
2. Распакуй архив **в отдельную папку**, например `NativeDLSS-0.1.0`.
   Не копируй DLL поверх LS вручную: так потеряется удобный откат.
3. Запусти `Install.cmd` и выбери существующую папку LS, в которой находится
   `LosslessScaling.exe`. Установщик проверит оригинал и сохранит старый
   `Lossless.dll` и INI в `native-dlss-backups`.
4. Оставь свой **рабочий SM86 `dxgi.dll`, совпадающий INI и runtime** на месте.
   Их архив не содержит и установщик не изменяет. Штатный DLSS FG не подходит
   для RTX 3080. Не обновляй мод до другой версии для этого теста.
5. В LS включи **LSFG3 → Fixed → ×2**, выключи HDR. Для LS выбери RTX 3080,
   подключённую к монитору; игровая карта остаётся прежней.
6. Оставь привычные параметры вывода LS, с которыми его родная генерация
   была плавной. Для 144 Гц можно сохранить прежний лимит игры 68 FPS.
7. Запусти масштабирование. Первый кадр после запуска/сброса остаётся штатным.

**В отличие от старого аддона, штатный LSFG должен оставаться включённым.**
Настройки LS передаются без изменений. Старые аддоны из `addons` этот прокси
не загружает. Папка старого runtime используется только как место поиска
NVIDIA DLL; это не запуск аддона/менеджера.

Backend ищет NVIDIA runtime в таком порядке: `native-runtime`, затем
`addons\LS_DLSSFG\runtime`, затем корень LS. Сохрани полный набор DLL
своей рабочей конфигурации. Если рабочий runtime уже находится в старой папке,
дублировать его не нужно. Процессный `dxgi.dll` должен остаться **в корне LS**.

## Настройки

Запусти `Settings.cmd` из папки сборки после установки. Изменения вступают
в силу после полного перезапуска LS. Можно также редактировать `NativeDLSS.ini`
в корне LS.

| Параметр | Смысл |
| --- | --- |
| Enabled | Включает экспериментальную подмену; 0 оставляет штатный LS |
| OpticalFlow | Использует NVOF; 0 передаёт нулевые векторы и требует оценки качества |
| Quality 1–5 | Скорость/точность NVOF и сетка 4/2 px; неподдерживаемая сетка 2 px заменяется 4 px |
| AnalysisPercent | Размер анализа в процентах по обеим осям; 50% — четверть числа пикселей, исходный цветной кадр DLSS остаётся полного размера |
| GPUOrdered | 1 связывает готовность через GPU fence; 0 подменяет только уже готовый результат и может часто возвращаться к LS |
| Slots 2–4 | Размер пула заданий; не меняет очередь или Max frame latency LS |

Начальные значения: Quality=2, AnalysisPercent=50, GPUOrdered=1, Slots=3.
Высокое качество Optical Flow увеличивает работу GPU. В первой версии LS
выполняет собственный анализ/синтез для надёжного возврата к штатному кадру:
поэтому одновременно оплачивается часть работы обоих генераторов.

## Проверка и откат

Лог — `logs\native-dlss-*.log` внутри LS. `eligible=1` означает допустимый
профиль; `step=ready` — успешную инициализацию; рост `submitted` — задания
backend; `composite_queued` — поставленные условные подмены. Флаг DLSS проверяется
на GPU непосредственно перед записью: запрет оставляет пиксели LS нетронутыми.
`flag_enabled_samples` / `flag_disabled_samples` — выборочные завершённые
задания, а не число показанных кадров. Сам лог не доказывает VRR.

При несовпадающей версии, недоступном FG, ошибке NVIDIA или переполнении пула
используется штатный кадр. GPU device removal может остановить и сам LS:
после него требуется перезапуск. Нет автоматической смены драйвера, лимита
игры, G-SYNC профиля или SM86-файлов.

Для возврата закрой LS, запусти `Restore.cmd`, выбери папку LS. Восстановится
последний сохранённый прокси и его INI; SM86-файлы не изменяются. Если DLL после
установки была заменена кем-то ещё, автоматический откат остановится, чтобы
не перезаписать новую версию; резервная копия остаётся доступной.

## Что проверено и что ещё требуется

Windows CI проверяет экспортный ABI, перехваты, пары исходных изображений,
реальные общие D3D11/D3D12 ресурсы, условную запись пикселей, запрет подмены,
восстановление состояния, сброс истории и переключение неподдерживаемого
профиля. Провайдер тестовых кадров существует только в тестовых EXE и
**отсутствует в пользовательском Lossless.dll**.

CI использует WARP и не запускает коммерческий LS, NVIDIA FG или твой SM86.
**Фактическая совместимость RTX 3080, качество интерполяции, кадровый график
и физический G-SYNC требуют запуска на твоём компьютере.** Сохранение всех
Present LS устраняет старую замену его вывода, но само по себе не гарантирует
ту же плавность: дополнительная GPU работа/зависимость ещё нуждается в проверке.
