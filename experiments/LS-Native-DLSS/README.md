# Native LS generation replacement research

Цель: улучшить качество промежуточных кадров с помощью DLSS FG, сохранив
захват, очередь, окно, временные позиции кадров и **все Present самого LS**.
Пользовательская система: две RTX 3080; игру рендерит карта без монитора,
LS работает на второй карте, к которой подключён монитор 3440×1440/144 Гц.
Первый целевой режим — Fixed ×2 SDR. Рабочего заменённого генератора пока нет.

## Что сделано

- Создана отдельная ветка `ls-native-dlss-research` от VRR6, без изменения Magpie.
- Проверены CRC исходного ZIP и SHA256 оригинальной DLL.
- Написан независимый read-only анализатор PE, ресурсов, DXBC/RDEF/SHEX и RTTI.
  Он воспроизводимо разбирает 202 compute-шейдера в 302 ресурсах исходной DLL.
  Шейдеры, веса, коммерческие DLL и пользовательские логи в код не включены.
- Найдены таблицы виртуальных методов LSFG2/LSFG3. Выполнено локальное
  дизассемблирование CPU-кода и прослежены создание шейдера и финальный Dispatch.
- Найден сильный кандидат финального синтеза: RCDATA **256**, пять SRV и один UAV,
  группа 16×16, `Timestamp` (float, offset 28) в 32-байтовом `cb`.
  Два входа связаны с чередующимися исходными изображениями; их временной порядок
  и смысл остальных трёх входов должны быть проверены, прежде чем включать подмену.
- Добавлен отдельно тестируемый контракт выбора готового кадра. Он запрещает
  подмену при другом устройстве, старом поколении ресурсов, другой паре кадров,
  фазе, размере, формате, цветном пространстве или незавершённой работе GPU.
- Добавлен Windows-инструмент локального дизассемблирования шейдеров через
  D3DDisassemble. Он открывает DLL как данные и не запускает её DllMain.

Подробные адреса и ограничения: [docs/native-mapping.md](docs/native-mapping.md).
План адаптера: [docs/integration.md](docs/integration.md).
Это исследовательские инструменты и контракт; установки или нового билда LS нет.

## Воспроизведение без запуска LS

Python 3.10+; сторонние Python-пакеты для анализа не нужны.
Укажите собственную оригинальную DLL. В установке менеджера она называется
`Lossless_original.dll`; его `Lossless.dll` является прокси.

```sh
python tools/analyze_dll.py /path/to/Lossless_original.dll --output local/inventory.json
python tools/verify_reference.py /path/to/Lossless_original.dll
python -m unittest discover -s tests -p 'test_*.py' -v
g++ -std=c++17 -Wall -Wextra -Werror -pedantic tests/test_slot_policy.cpp -o /tmp/slot-policy
/tmp/slot-policy
```

В Developer Command Prompt для Visual Studio/Windows SDK:

```bat
cl /std:c++17 /EHsc tools\disassemble_shaders.cpp /link d3dcompiler.lib
disassemble_shaders.exe C:\LS\Lossless_original.dll local\shader-assembly
```

Каталог `local/` и коммерческие исполняемые файлы исключены из git.
CI проверяет парсер, контракт и компиляцию исследовательского Windows-инструмента.
CI **не проверяет DLSS, RTX 3080, реальный frame pacing или физический VRR**.

## lsfg-vk

[Рассказ автора о восстановлении LSFG](https://lsfg-vk.dev/blog/porting-lsfg-to-native-vulkan/)
используется как описание методики. Его Vulkan-вывод не переносится в наш проект.
Текущий v2 имеет CC BY-NC-ND; авторский код и таблицы проходов не скопированы.
Собственные выводы здесь получены из предоставленной пользователем DLL.
Смена условий описана [автором](https://lsfg-vk.dev/blog/important-changes-to-lsfg-vk/).
