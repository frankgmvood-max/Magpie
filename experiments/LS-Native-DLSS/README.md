# Native LS generation replacement research

Цель: улучшить качество промежуточных кадров с помощью DLSS FG, сохранив
захват, очередь, окно, временные позиции кадров и **все Present самого LS**.
Пользовательская система: две RTX 3080; игру рендерит карта без монитора,
LS работает на второй карте, к которой подключён монитор 3440×1440/144 Гц.
Первый целевой режим — Fixed ×2 SDR. Реализован экспериментальный standalone
backend без менеджера аддонов. Новые логи после смены SM86 подтверждают
задания NVIDIA и разрешённый disable flag; пользователь сообщает о плавности
и работающем VRR. Качество кадров и временные интервалы требуют измерения;
успешные тесты WARP не подтверждают NVIDIA FG или VRR.

## Сборка 0.3.1: исправление запуска родного интерфейса

При загрузке BAML выбор FG приходит до создания наших настроек. В 0.3.0
новый обработчик выбрасывал исключение перед исходной проверкой IsLoaded.
В 0.3.1 раннее событие проходит через штатную защиту LS. Добавлены реальный
WPF-тест этого порядка, воспроизведение на исходном коде 0.3.0 и диагностический
запуск для получения ошибки с пользовательского ПК. Повторное исследование
REA и границы доказательств: [analysis/REA-STARTUP-0.3.1.md](analysis/REA-STARTUP-0.3.1.md).
Установщик также снимает метки скачивания с DLL своего пакета перед LoadFrom.
Генератор, расписание кадров, SM86 и NVIDIA Inspector этой правкой не менялись.

## Сборка 0.3.0: родной интерфейс LS

В Frame Generation → Type добавлен DLSS. Собственные настройки Optical Flow,
фильтров и HUD встроены в существующую карточку; выбор и параметры сохраняются
обычным XmlSerializer в родном профиле LS и копируются вместе с профилем.
Существующие типы FG сохраняют штатные обработчики и все native параметры.
Новый bridge управляет экономичным/штатным режимом, без INI-горячих клавиш,
противоречащих выбранному Type. Optical Flow quality по-прежнему требует
полного перезапуска LS, поскольку GPU-графы сохраняются между сессиями.
Установщик проверяет точную managed DLL, патчит её локально и делает откат
интерфейса, backend и значения DLSS в XML. Чужой патченый бинарник не публикуется.

REA 6.3.0 действительно использован через managed MCP provider и bounded native
bridge: [analysis/REA-NATIVE-UI.md](analysis/REA-NATIVE-UI.md).
Отдельная семантическая проверка Cecil подтвердила сохранность 533 исходных
объявлений, native P/Invoke и ресурсов; изменены ровно шесть необходимых методов.
Аппаратная приёмка новой версии на двух RTX 3080/SM86/VRR не выполнена.

## Сборка 0.2.0

Добавлен экономичный обход 25 GPU-проходов LS по новому фактическому анализу
REA 6.3.0 / Ghidra 12.1.4. Контракт и границы доказательств:
[analysis/REA-BYPASS.md](analysis/REA-BYPASS.md).
Есть три режима, независимые настройки Optical Flow, восемь областей HUD,
полное сравнение RGB для повторов, защита смены сцены и сброс истории,
явно выбираемые профили приложений, горячие клавиши и timestamp-диагностика GPU.
Инструкция установки и реальные ограничения:
[package/README-RU.md](package/README-RU.md).

Курсор, Present и конфигурация NVIDIA Inspector не меняются. Экономичный режим
пропускает проверенные Dispatch, но сохраняет CPU-методы и выделение ресурсов LS.
Новая аппаратная приёмка NVIDIA/SM86/двух GPU ещё не выполнена.
Следующий раздел описывает сохранённую рабочую основу 0.1.4, а не доказательство
аппаратной работы нового обхода.

## Сборка 0.1.4

В длинном новом логе 0.1.2 после четвёртой сессии DLSS перестаёт получать
задания, хотя LS продолжает создавать устройства и исходные изображения.
`session_limit` доходит до 10 289. Исправлено пожизненное исчерпание пула:
неактивный граф после завершения GPU-работы переоткрывается на новом D3D11
устройстве того же адаптера и размера. NGX/NVOF и их D3D12-ресурсы сохраняются;
история сбрасывается, первый промежуточный кадр остаётся штатным.
В лог добавлены текущий контекст, причина выбора backend и счётчики повторных
подключений. Подробности и границы проверки: [docs/session-lifecycle.md](docs/session-lifecycle.md).
Это исправляет обнаруженный возврат к LS при повторных запусках FG; причину
исчезновения потолка исходных 68 FPS эти логи не устанавливают.

Сохраняется диагностика 0.1.3: явная загрузка распознанного SM86 `version.dll` исходного архива до NGX,
фиксирует путь фактически загруженного модуля, runtime-файлы и отдельные ответы
capability. Ограниченный callback NGX копирует сообщения в очередь без I/O
и ожиданий; диагностический worker пишет их после освобождения mutex backend.
Сборщик `Collect-Logs.cmd` объединяет логи LS/NGX/SM86 и метаданные DLL.
Это исправление порядка загрузки и диагностическое обновление, а не подтверждение
работы SM86/FG на реальном GPU. Подробности: [docs/ngx-runtime.md](docs/ngx-runtime.md).

REA подключён и адаптирован для анализа DLL через Ghidra. Повторно проверены
семь CPU-функций LS и вызывающий цикл: [docs/rea-integration.md](docs/rea-integration.md).
В 0.1.2 запись диагностического лога освобождает блокировки до вывода в файл;
медленный лог больше не удерживает mutex обработки исходных изображений.
Добавлены WARP-проверка этого случая и лог фактического Optical Flow grid.

Установка, настройки и ограничения: [package/README-RU.md](package/README-RU.md).
Windows-пакет содержит `Lossless.dll`, установщик с резервной копией/откатом,
INI, отдельное окно настроек Optical Flow и лицензии. LS, NVIDIA runtime
и мод SM86 не включены.

Новый [backend](backend/native_backend.cpp) подключён после штатной записи
исходного кадра 254 и после штатного синтеза 256. Два исходных изображения
снимками передаются на D3D12-устройство **того же адаптера LS**. NVOF использует
явные D3D12 fence points; его current→previous смещения разворачиваются в
полноразмерные векторы и нормализуются согласно NGX SDK. DLSS FG готовит ×2
midpoint. Перед записью в выход LS shader проверяет фактический disable flag
на GPU. Запрет/несовпавшая пара сохраняет пиксели LS.

LS продолжает выполнять свои анализ и синтез и остаётся владельцем всех Present.
В callback нет CPU fence wait, Flush, собственного swapchain или ограничителя
игры. По умолчанию зависимость готовности **ожидается на GPU**; дополнительное
GPU время ещё требует проверки кадрового графика. Ready-only вариант доступен
настройкой, но результаты могут часто не успевать: штатный D3D11 stream может
отправляться только на последующем Present.

Удерживается до четырёх графов ресурсов до завершения процесса. Неактивные
графы после GPU retirement переиспользуются для нового контекста того же
адаптера/размера/формата. При несовместимых или ещё занятых графах — LS fallback.
Изменение профиля, разрыв поколения или пауза >250 мс сбрасывают историю NGX.
Первый результат после сброса остаётся штатным.

## Что сделано

- Создана отдельная ветка `ls-native-dlss-research` от VRR6, без изменения Magpie.
- Проверены CRC исходного ZIP и SHA256 оригинальной DLL.
- Написан независимый read-only анализатор PE, ресурсов, DXBC/RDEF/SHEX и RTTI.
  Он воспроизводимо разбирает 202 compute-шейдера в 302 ресурсах исходной DLL.
  Шейдеры, веса, коммерческие DLL и пользовательские логи в код не включены.
- Найдены таблицы виртуальных методов LSFG2/LSFG3. Выполнено локальное
  дизассемблирование CPU-кода и прослежены создание шейдера и финальный Dispatch.
- Найден сильный кандидат финального синтеза: RCDATA **256**, пять SRV и один UAV,
  группа 16×16, `Timestamp` (float, offset 28) в 32-байтовом `cb`.
  Для найденного CPU-пути установлен порядок: `t0` — предыдущее изображение,
  `t1` — новое. Подтверждение на контролируемых изображениях LS ещё требуется.
- Найдена более ранняя запись исходного изображения: RCDATA **254**, группа 8×8,
  вход `t0` и выход `u0`, перед подготовкой optical flow. Наблюдатель теперь
  отслеживает поколения этих записей и сопоставляет их с парой финального синтеза.
  Пропуски, смена ресурсов и посторонние отслеживаемые записи разрывают историю.
  Полное покрытие всех способов изменения пикселей пока не обеспечено.
- Добавлен отдельно тестируемый контракт выбора готового кадра. Он запрещает
  подмену при другом устройстве, старом поколении ресурсов, другой паре кадров,
  фазе, размере, формате, цветном пространстве или незавершённой работе GPU.
- Добавлен Windows-инструмент локального дизассемблирования шейдеров через
  D3DDisassemble. Он открывает DLL как данные и не запускает её DllMain.
- Написан самостоятельный наблюдатель `observer/Lossless.dll`, без менеджера
  аддонов и его SDK. Десять штатных экспортов передаются PE-forwarder'ами;
  `ApplySettings` передаёт все 32 аргумента и запускает наблюдение вне DllMain.
  Наблюдение выключено по умолчанию. Экспериментальный backend включается
  отдельным разделом NativeDLSS и меняет только условно выбранные пиксели.
- Фаза берётся из CPU-данных при создании динамического constant buffer, с отслеживанием последующих изменений.
  Для найденного CPU-прохода реальная аллокация — **48 байт**, хотя RDEF
  описывает только 32. Нет чтения GPU через Map, дополнительных GPU-копий,
  ожиданий, Flush, Present или ограничения частоты кадров.
- Добавлены анализатор JSONL-трассы, проверяемая очередь наблюдений и Windows
  ABI-fixture для 32 аргументов и десяти forwarder'ов. Собрана Windows x64 DLL
  кросс-компилятором; это не запуск на Windows и не проверка плавности на GPU.
- Windows CI затем успешно собрал прокси через MSVC и выполнил первоначальные четыре теста:
  очередь, выбор кадра, все аргументы/forwarder'ы, реальные WARP-перехваты
  создания буфера и инвалидирования фазы. Отдельно проверены все 11 экспортов
  и исходные ordinal'ы. Это проверка самостоятельного прокси на WARP, не DLSS/VRR.
- Продолжен статический разбор финального синтеза: два двунаправленных поля
  смещений и отдельные четыре веса смешивания. Простая замена одного поля
  на NVOF недостаточна: [docs/synthesis-inputs.md](docs/synthesis-inputs.md).
- Добавлен отдельный пул GPU-снимков исходных изображений D3D11 → D3D12:
  проверяется устройство/адаптер, защищены поколения сессии и время чтения
  обоих входов. Пул ограничен, без CPU-ожиданий, Flush и Present. Он пока
  не подключён к перехватам LS; номера записей не объявляются кадрами игры.
  Контракт и Windows-проверка: [docs/input-snapshots.md](docs/input-snapshots.md).
- Реализована обратная передача готового изображения D3D12 → D3D11 с отдельным
  удержанием результата до завершения нативной GPU-копии. Неизвестный результат,
  запрет интерполяции и непроверенный слот оставляют штатный кадр. Проверка
  транспорта использует копирующий backend; это ещё не работа DLSS внутри LS.

Подробные адреса и ограничения: [docs/native-mapping.md](docs/native-mapping.md).
План адаптера: [docs/integration.md](docs/integration.md).
История выше описывает этапы исследования. DLSS/NVOF теперь подключены;
классы bridge остаются изолированными проверками транспорта. Production
backend использует собственный ограниченный job ring и GPU gate.
Самостоятельная схема описана в [docs/standalone-observer.md](docs/standalone-observer.md).

## Воспроизведение без запуска LS

Python 3.10+; сторонние Python-пакеты для анализа не нужны.
Укажите собственную оригинальную DLL. В установке менеджера она называется
`Lossless_original.dll`; его `Lossless.dll` является прокси.

```sh
python tools/analyze_dll.py /path/to/Lossless_original.dll --output local/inventory.json
python tools/verify_reference.py /path/to/Lossless_original.dll
python -m unittest discover -s tests -p 'test_*.py' -v
g++ -std=c++17 -Wall -Wextra -Werror -pedantic tests/test_slot_policy.cpp -o /tmp/slot-policy
/tmp/slot-policy
```

В Developer Command Prompt для Visual Studio/Windows SDK:

```bat
cl /std:c++17 /EHsc tools\disassemble_shaders.cpp /link d3dcompiler.lib
disassemble_shaders.exe C:\LS\Lossless_original.dll local\shader-assembly
```

Каталог `local/` и коммерческие исполняемые файлы исключены из git.
Windows сборка с официальным SDK revision
`374959484e79a640feaba44c93ac8cfb0a03f5b5`:

```bat
cmake -S observer -B build/native -A x64 -DLS_ENABLE_NGX=ON -DNGX_ROOT=C:\sdk\DLSS
cmake --build build/native --config Release --parallel
ctest --test-dir build/native -C Release --output-on-failure
```

CI проверяет парсер, контракт, экспортный ABI, перехваты, GPU transport,
условные записи пикселей, disable flag, сброс/профиль, установку и откат.
CI **не проверяет DLSS, RTX 3080, реальный frame pacing или физический VRR**.
